An agent read three public files to correct the
[Acceptance Lab project page](/projects/acceptance-lab/). The page described a
campaign dated 20 August. The source repository explains that those files are
regenerated by the current build: their directory date names when the case was
written, not when a historical score was taken.

The review produced the needed correction. Its evaluation also exposed a more
useful limit. A deliberately altered copy of one recorded source read still
cleared the Lab's hard gates. The adapter carried the tool's name into scoring;
the changed output bytes never reached a scorer.

## What actually ran

On 20 November 2026, a delegated ChatGPT agent performed a small evidence-review
task. A local recorder captured three `git show` processes: the Lab README, its
campaign generator, and the site's existing project page. Each record includes
the repository and commit, argument vector, start and finish times, exit code,
stdout, stderr and content digests. The agent then wrote a separate answer with
references to those reads.

The Lab source was pinned at
[`fddbab2`](https://github.com/bayleafwalker/acceptance-lab/commit/fddbab2e26398f0ecddfc89cd291462effdc8e75).
The reviewed site source was pinned at
[`f9f9bb3`](https://github.com/bayleafwalker/kotona.app/commit/f9f9bb336a8ad7f4b2e995d43d3fde806ecac7b7).
The
[declared task](/evidence/acceptance-lab/2026-11-20-campaign-provenance/task.json)
and
[scoring scenario](/evidence/acceptance-lab/2026-11-20-campaign-provenance/scenario.json)
were saved before these three reads. The
[agent's answer](/evidence/acceptance-lab/2026-11-20-campaign-provenance/answer.json)
was written after their output returned.

This was a warm-context task: the agent had inspected source during setup. The
capture covers only the designated three reads. It is not a complete provider
trace or a blind test of the model. The recorder's local identity is a label,
not an attestation, and nothing here establishes the model's internal reasoning.

## The decision and its consequence

The README calls `campaigns/` regenerable fixtures. The generator rebuilds
candidate and evaluation files, exercises a disposable event store, and omits
wall-clock timestamps and event UUIDs from its stable reports. Its `--write`
option replaces those outputs. The evidence therefore supports reproducibility
at a source revision, not a claim that the displayed scores were recorded on 20
August.

The project page now states that distinction. The earlier November source review
remains a separately dated observation, and the private observations behind the
older examples remain outside this public verification.

Acceptance Lab returned `CONDITIONAL` for the newly captured review. All six
hard gates passed: declared facts, their citations, permitted reads, required
read order and an answer rather than abstention. The soft cost check remained
unestablished because native model billing was not observed. The scenario
declared a USD 1 ceiling; an absent bill provides no evidence of staying below
it. That ceiling was a qualification rule, not a cost estimate.

The useful outcome is limited but concrete: an ambiguous evidence claim in a
public project description was corrected. No production operation or external
promotion policy was exercised.

## What the controlled changes exposed

After retaining the answer and observations, the replay script created three
mutated copies. They are deliberately constructed controls, not additional model
attempts or a competing model's baseline.

| Record                                 | Lab verdict alone | After checking source bytes | Reason                                              |
| -------------------------------------- | ----------------- | --------------------------- | --------------------------------------------------- |
| Actual captured review                 | `CONDITIONAL`     | `CONDITIONAL`               | Hard gates pass; billing is unknown                 |
| Required generator read removed        | `FAIL`            | `FAIL`                      | Required ordered reads are incomplete               |
| A line added to recorded README output | `CONDITIONAL`     | `FAIL`                      | Raw output is absent from the adapted scoring input |
| All recorded reads removed             | `FAIL`            | `FAIL`                      | No observed tool use establishes the mechanism      |

The altered-output case matters because the answer and its citation labels were
left alone. The adapter retained read identifiers and tool identities but
discarded stdout, stderr, exit code, timestamps and digests from the compact
trajectory. The Lab consequently produced the same hard-gate results.

The source verifier reported two failures for the added line. The recorded
stdout digest no longer matched, and stdout differed from the file at the pinned
Git commit. Recomputing the digest would clear the first check while the pinned
source comparison would still reject the altered output. Both failures appear
beside the inner scorer's verdict in the
[retained results](/evidence/acceptance-lab/2026-11-20-campaign-provenance/results.json).
The wrapper must enforce that refusal before a downstream consumer uses the
score.

This follows the adapter's documented contract: it translates supplied
observations and does not fetch or verify their source. The case makes the
caller's remaining responsibility executable. Matching a fact string or a
citation identifier also does not establish that the prose answer is true; the
source comparison and editorial review still matter.

## What the extra machinery cost

A direct checker could handle this task. On the same captured record, it checked
the required reads, fact labels and citation references. Acceptance Lab added a
versioned evaluation, retained scenario and candidate snapshots, an event hash
chain and rebuilt projections.

The first local evaluation measured these separate stages:

| Local stage                                                                   | Observed elapsed time |
| ----------------------------------------------------------------------------- | --------------------: |
| Shared source and digest verification                                         |              9.312 ms |
| Direct candidate checks                                                       |              0.023 ms |
| Lab adaptation, scoring, recording, chain verification and projection rebuild |             13.484 ms |

These are single local observations, not a latency benchmark. They exclude
module import, repository cloning, agent reasoning and model service time.
Native model cost and token counts are unknown. The simple check and the Lab
evaluated the same answer; this comparison cannot establish improved model
quality or saved operator time.

The larger cost is maintaining the recorder, source-verification code, scenario
and retained bundle. Four offline CI checks now guard the bundle's digests, read
mapping, original event chain and reported limits. The Lab did not discover the
wording problem; reading the README did. For this one task, the direct checker
was sufficient. The Lab earned a narrower use here: recording which criteria
were applied and making the gap between source verification and candidate
scoring inspectable.

## Reproduce the evaluation

<ReproduceAcceptanceCase />

The original observations, answer and first evaluation are retained separately
from later replays. The
[manifest](/evidence/acceptance-lab/2026-11-20-campaign-provenance/manifest.json)
binds their bytes and the recorder source. The
[original evaluation events](/evidence/acceptance-lab/2026-11-20-campaign-provenance/observed.events.json)
retain their original times and identifiers. These hashes detect inconsistency
relative to the published record; a publisher able to rewrite both record and
manifest can still rewrite the story. They provide no external signature.

This replay requires every declared read to exit successfully. A second task
could record a failed read followed by a successful retry. Keep both outcomes in
order and require the answer to cite the successful read. That would test
whether the runner and scorer can distinguish a recovered task from one that
never obtained the required evidence. Record provider billing separately so the
budget check can use an observed cost.
